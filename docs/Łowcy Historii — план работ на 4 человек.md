# Łowcy Historii — план работ на 4 человек

Oct 10, 2026 · @Oleg

## Как читать план

Две фазы. **Фаза 1 (сейчас – 01:00):** все четверо строят продукт на заглушках, без деплоя и без настоящего контента. **Фаза 2 (01:00 – 06:00):** генерация контента и деплой. Дальше onepager до 8:00 и финальная сдача до 12:00.

Время в плане ориентировочное: если старт сдвинулся, сдвигайте все блоки. Главное — контрольные точки в 21:00 и 01:00: к ним цикл раунда должен работать целиком.

| Человек | Фаза 1: что строит | Фаза 2: чем занят | Где пишет код |
| --- | --- | --- | --- |
| A — бэкенд, лидер | FastAPI: вход, места, раунды, попытки, очки, магазин, лидерборд | Деплой сервера, загрузка контента в прод | `api/`, `docker/`, `docker-compose.yml`, `.env.example`; заглушка в `worker/`, пока C на съёмке |
| B — мобилка 1 | Игровой цикл: карта, задание, камера, проверка, результат | Демо-режим, сценарий демо, багфиксы, сборка APK | `mobile/`: экраны входа, карты, задания, камеры, результата; каркас навигации и `src/api/` |
| C — ML | Воркер распознавания: эмбеддинги, поиск по эталонам, пороги, LLM-судья | Эталонные фото 6–8 мест, задания и подсказки, настройка порогов | `worker/`; в `content/` — `fetch_places.py`, `add_refs` |
| D — мобилка 2 | Лента рилсов, экран награды, профиль, магазин, обучение | Генерация рилсов: факты → сценарий → озвучка → видео | `mobile/`: экраны рилсов, награды, профиля, лидерборда, магазина, обучения; в `content/` — `generate_reel.py` |

Имена впишите в первую колонку.

**Общие места:** `openapi/openapi.yaml` правится только по договорённости всей команды. В `mobile/` общие для B и D `src/components/`, `src/constants/theme.ts` и корневой `src/app/_layout.tsx`: прежде чем менять, предупреди второго. `src/api/schema.d.ts` генерируется командой `npm run gen:api`, руками его не правим. Лезешь в чужую папку — сначала скажи владельцу, ревью PR делает он.

**Одно исключение из правила «контент в конце».** Свои тестовые фото памятников нужно снять при дневном свете, а закат во Вроцлаве сегодня около 18:20. Без этих фото в фазе 2 нечем подобрать порог распознавания. Поэтому сразу после шага 0 один человек (C) уходит снимать на 40–60 минут, а заглушку воркера за него пишет A, остальное — строго по плану.

**Касается всех частей:**

- Интерфейс, задания, подсказки, субтитры и озвучка рилсов — на польском (НФТ-08). Фразы в этом плане на русском только для понятности.
- Приватность (НФТ-06): фото игрока удаляется после проверки, координаты не хранятся после раунда.
- Очки и XP — разные вещи: XP только для лидерборда, очки — валюта магазина. Места за очки не открываются.

## Шаг 0. Старт вместе (16:30 – 17:30)

За этот час все договариваются о контракте и поднимают каркас, чтобы дальше каждый мог работать независимо, не дожидаясь других.

1. **Контракт API (все, 20 мин).** Берём сводку эндпоинтов из документа «архитектура и стек» и фиксируем в OpenAPI: пути, поля запросов и ответов, коды ошибок (`too_far`, `wrong_place`, `insufficient_points`, `email_taken`, `invalid_credentials`, `nickname_taken`). После этого контракт меняем только вслух, всей командой.
2. **Репозиторий (A, 10 мин).** Монорепо: `api/`, `worker/`, `mobile/`, `content/`. Ветка `main` всегда запускается; каждый работает в своей ветке и сливает через PR.
3. **Локальный docker compose (A, 20 мин).** `api`, `worker`, Postgres с PostGIS и pgvector, Redis, MinIO. Это не деплой, а среда разработки: `docker compose up` на ноутбуке A.
4. **Каркас мобилки (B, 20 мин).** Expo + TypeScript + expo-router, нижняя навигация из прототипа, TS-клиент из OpenAPI. Проект открывается на телефоне каждого.
5. **Заглушки (C и D, 20 мин).** Два тестовых «места»: одно — предмет прямо в зале хакатона, второе — что-то у входа. По 5 своих фото на каждое. Плюс 2–3 любых вертикальных MP4 как заглушки рилсов. С ними весь цикл можно гонять, не выходя на улицу.
6. **Ключи и аккаунты (D, 10 мин).** Создать сейчас, хотя понадобятся только в фазе 2: LLM API, TTS, Cloudflare (R2), сервер (Hetzner или Railway), Expo (EAS). Ключи — в общий `.env.local`, не в git. В 02:00 ночи на регистрацию времени не будет.
7. **Список мест (все, 5 мин).** Выбрать 6–8 памятников в центре, по возможности рядом друг с другом. Нужен C для дневной съёмки.

Три мелочи шага 0, которые съедают час, если про них забыть:

- Готового официального образа Postgres сразу с PostGIS и pgvector нет: собрать свой Dockerfile на базе `postgis/postgis` с пакетом `pgvector`. Этот же образ пойдёт на сервер.
- Wi-Fi площадки часто изолирует устройства друг от друга. Если телефон не видит IP ноутбука — туннель cloudflared или ngrok.
- Репозиторий должен быть открыт для жюри (публичный или с доступом) — ссылку сдаём до 12:00.

**Готово, когда:** контракт в репозитории, `docker compose up` поднимает всё, Expo-приложение открывается на телефонах, есть тестовые места и MP4-заглушки.

## Если не успеваем и правила работы

**Режем в таком порядке** (сверху — первым):

1. Мини-игра дома, тематические маршруты, партнёрские награды
2. Сброс пароля и подтверждение e-mail: оставить кнопку-заглушку
3. Комментарии и «Поделиться» с реферальной ссылкой
4. Магазин: оставить только покупку подсказки
5. LLM-судья: оставить GPS + CLIP с одним порогом
6. Лидерборд в Redis: заменить обычным SQL-запросом
7. Число мест: 6 вместо 8

**Не режем никогда:** полный цикл раунда, демо-режим, карточку источников в рилсах.
